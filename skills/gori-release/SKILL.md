# Deliver the selected task

1. Confirm the complete request, review findings, affected feature-map and driver reconciliation, user-path evidence, exact revision/tree and repo release contract. Resolve any supported finding or stale proof before a completion claim.
2. Run the repo's full local pre-push gate. Prepare coherent commits and an existing-format PR or release record with outcome, before/after proof, blast radius, rollback and unproven layers. Follow the repo's Git and authorization rules.
3. After an authorized push, inspect required CI. For a deployment, confirm the ready deployment, production smoke and rollback under the repo's sequence. A local browser pass never substitutes for those gates.
4. Record implemented, reviewed, locally verified, CI-verified and production-verified separately. State the exact remaining action if any gate is blocked. Recommend the board status the user should apply; never change Project items or create new tasks.

Completion means the agreed endpoint actually happened with evidence. If authority stops before release, hand off the prepared change and name that boundary without calling the task shipped.
